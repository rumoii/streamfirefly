# StreamFirefly 0.10.0 Beta 6 内测版

仅面向受邀测试人员，以私有 Pre-release 分发，不是稳定版、浏览器商店正式版或完整 1.0 验收。测试包版本为 `0.10.0-beta.6`，扩展和 Native Host 数字版本仍为 `0.10.0`。已有 Beta 版本及其 Release 附件保留，不覆盖历史版本。

## 相对 Beta 5 的更新

- 下载代理新增“跟随 Windows 系统代理”“直连”和“自定义代理”三种模式。系统模式读取 Windows 固定代理，自定义模式仅接受无账号密码的 HTTP/HTTPS 地址。
- 普通 HTTP 下载与 HLS/DASH 分片统一使用任务创建时的网络策略；直连和自定义模式显式设置 curl 代理参数，避免被环境代理变量覆盖。
- 扩展在任务创建、列表恢复和控制前向 Native Host 同步网络配置，并通过 `network-policy-v1` 能力拒绝新旧组件混用。任务存储格式不变，网络配置不写入 `tasks.json`。
- 注入网页的工作区品牌图标改为内联 PNG，避免网页相对路径导致图标失效。
- 下载输出根据 MIME、扩展名和流任务类型显示“图片”“音频”“视频”或“媒体”，字幕仍显示语言或字幕标识。

## 支持范围

- 支持 Windows 固定 HTTP/HTTPS 系统代理、显式直连和无认证的自定义 HTTP/HTTPS 代理。
- 暂不支持 PAC、WPAD、SOCKS 代理及代理账号密码。需要 PAC/WPAD 的环境应先解析出明确的 HTTP/HTTPS 代理地址，再使用自定义模式。
- 本批不增加旧协议兼容层；扩展与 Native Host 必须成套更新。

## 更新与恢复

升级前结束活动任务、关闭浏览器并退出助手，备份 `%LOCALAPPDATA%\StreamFirefly\tasks.json`、同目录的 `tasks` 检查点目录和已下载文件。界面版本仍为 `0.10.0`，通过包名、Release 和 `PACKAGE-INFO.json` 区分 Beta 6。

回退时先保留升级后的数据副本，再成套恢复上一版扩展、Native Host 和必要的升级前备份。不要用旧组件继续处理唯一一份新版本任务数据。

## 发布门槛

只发布最终源码 SHA 的干净构建。源码验证、扩展构建与校验、完整单元和契约测试、浏览器夹具、Rust 测试、Native HTTP/HLS/DASH/队列/捕捉链路、双架构构建与包审计，以及 x64 安装态 Chrome/Edge 短流程均已完成。包内 `PACKAGE-INFO.json` 必须记录相同源码提交且 `sourceDirty` 为 `false`。

本次 GitHub Actions 运行已通过上述源码、构建和安装态步骤，但三个 Artifact 上传步骤因账号 Actions 存储配额失败，因此附件由同一最终源码 SHA 在 Windows 本机重新构建、审计并完成安装态验证后直接上传到私有 Release。不得把 Actions 运行描述为附件来源，也不能复用其他源码提交的产物。x64 安装态验证不代表真实网站或长期运行已经验收；ARM64 仅完成构建和包审计，不代表 ARM64 设备实机通过。

## 验收边界

- 真实网站下载、企业代理与认证代理、ARM64 实机、旧版本升级与回退、7200 秒长期运行和浏览器商店交付仍需独立验收。
- 自动化浏览器使用 localhost 夹具；真实 Windows 系统代理下载只证明当前开发机固定代理链路，不替代其他网络环境。
