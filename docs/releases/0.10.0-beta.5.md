# StreamFirefly 0.10.0 Beta 5 内测版

仅面向受邀测试人员，以 Pre-release 分发，不是稳定版、浏览器商店正式版或完整 1.0 验收。测试包版本为 `0.10.0-beta.5`，扩展和 Native Host 数字版本仍为 `0.10.0`。已有 Beta 版本及其产物保留，不覆盖历史 Release。

## 相对 Beta 4 的更新

- Blob 视频不再走无法成立的普通预览、内置下载或外部工具路径；扩展记录 `URL.createObjectURL(MediaSource)` 的精确对应关系，并从资源行进入匹配媒体源的缓存捕捉。
- Chromium 在网页工作区就绪后关闭原生侧栏，收起工作区时先恢复侧栏；Firefox 保留原生侧栏。打开、关闭或恢复失败时保留仍可用的入口并显示明确错误。
- 外部工具确认页增加返回资源页和关闭确认页路径，不再让用户停留在无法返回的独立页面。
- 删除与类型筛选重复的类型分组排序，保留发现顺序、大小和时长排序；HLS 预览模块改为按需加载。
- Chromium 最低支持版本调整为 141，以使用确定的 `sidePanel.close()` 能力。

## 更新与恢复

扩展与 Native Host 继续成套更新。Native 协议、任务存储版本和捕捉帧格式不变；本批不增加新旧扩展混用适配。升级前结束活动任务、关闭浏览器并退出助手，备份任务文件、检查点目录与已下载文件。界面版本仍为 `0.10.0`，通过包名、Release 和 `PACKAGE-INFO.json` 区分 Beta 5。

回退时先保留升级后的数据副本，再成套恢复上一版扩展、Host 和必要的升级前备份。不要用旧组件继续处理唯一一份新版本任务数据。

## 发布门槛

只发布最终源码 SHA 的干净 CI 构建。先运行完整短流程，再对同一源码提交运行 7200 秒安装态捕捉；类型、构建、单元与契约、三浏览器资源和发现、HLS/DASH 下载闭环、真实 Native、双架构包审计、x64 安装态捕捉、内存预算、收尾和卸载清理必须通过。任一失败均阻止 Release，不能复用 Beta 4 产物或其他源码提交的证据。

Release 正文记录最终源码 SHA、成功流水线、两小时结果和附件 SHA-256。附件仅使用两小时成功流水线生成的 x64、ARM64 ZIP 与 `INTERNAL-SHA256SUMS.txt`；包内 `PACKAGE-INFO.json` 必须记录相同源码提交且 `sourceDirty` 为 `false`。

## 验收边界

- Blob 精确映射仅适用于页面通过 `URL.createObjectURL(MediaSource)` 创建、仍属于当前文档的媒体源；不读取启动前缓存，不支持 WebRTC 录制或 DRM。
- 真实网站、真实外部下载器、ARM64 实机、升级回退和浏览器商店交付仍需独立验收。自动化夹具和两小时运行不能替代这些边界。
- Firefox XPI 未经 Mozilla 签名，仅用于临时载入测试。
