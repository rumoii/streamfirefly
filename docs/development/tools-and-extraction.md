# 工具交接、规则提取与设置界面

## 开发状态

开发基线为 `36903e4`，开发日期为 2026-09-08。工具配置、规则调试、URL 提取和设置界面已实现，版本保持 `0.10.0`。正式安装态、真实工具、真实网站与长时验收由用户统一安排，以下开发检查不能替代这些验收，也不代表新版本已发布。

## 工具配置与交接

- Aria2 支持保存目录与可选输出文件名模板，生成 RPC 的 `dir`、`out`；输出文件名按现有文件名校验处理。
- 新增 N_m3u8DL-RE 表单，配置保存目录、名称模板、自动选择轨道和授权请求头。路径与每个参数分离，不经过 shell；空的条件参数省略。
- 表单使用 `IntegrationProfile.programOptions`，与高级 `arguments` 互斥。转换高级参数会删除结构化选项，之后仅编辑参数列表；普通 EXE、HTTP 和协议配置保持各自职责。
- `integration.test` 接收 `{ profile, secret }` 草稿，不保存配置、令牌或回执。程序只调用 Native `integration.test` 检查文件和参数；Aria2 只查询版本，不创建下载任务。测试令牌来自当前输入框，实际交接的会话令牌仍需显式应用。
- `shared/tool-options.ts` 负责参数模板生成与安全诊断；`integration-request.js` 是预览和调用共用的参数准备入口，适配器拥有传输。回执只表示接收、启动、失败或未知；不管理外部下载进度，未知结果不自动重试。

## 规则调试与提取

`discovery.test` 接收 `{ config, sample }`，返回分类与逐条解释。生产与草稿测试使用同一匹配核心；草稿不落盘、不收集资源、不触发工具，也不改变生产规则的超时停用状态。排除优先、列表顺序、站点及大小语义不变。

独立 `extractionConfig` 为 `{ version: 1, rules }`，通过可信扩展设置页的 `extraction.get/save/test` 管理。规则包含 `id/name/enabled/sites/pattern/flags/output/decode/kind`；正则仅支持 `i/u`，输出模板以 `$0` 表示整体匹配、`$1` 至 `$99` 表示捕获组。首条匹配最多产生一个地址，输出失败即结束，不递归提取。规则数量最多 100，输出和正则执行沿用可终止 Worker。

- `shared/extraction.ts` 负责匹配、捕获组替换、单次解码和地址校验；相对地址按原请求 URL 解析，仅允许不带用户名密码的 HTTP/HTTPS。
- `extension/src/extraction.js` 拥有配置、串行保存和生产超时停用状态；调试不影响这些状态。配置写入失败不清理候选，旧配置与超时停用状态不变。
- `resources.js` 拥有候选、去重和清理。提取结果经过现有分类及排除规则；`extraction` 来源记录保留规则 ID、原始地址、预期类型和是否观察到目标网络请求。
- 提取候选不复制原请求的 Cookie、Authorization、Referer、大小、MIME 或附件信息，不触发外部自动发送。真实目标请求到来后才补充其请求元数据；原始资源不被替换，结果不递归回送提取器。
- 保存提取配置会清除仅由旧规则产生、尚未实际观察到的候选，包括会话存储内尚未载入的标签页；已观察到的目标和已创建下载任务不删除。

### 保存结果与重试

配置与候选分别存储在 `storage.local` 和 `storage.session`，不提供跨存储原子事务。配置写入失败通过消息的 `ok: false` 返回；写入成功返回 `ExtractionSaveResult`，包含实际配置、超时停用状态和 `cleanup`：`{ status: "complete" }` 或 `{ status: "failed", error }`。外层 `ok: true` 表示已取得保存结果，不代表清理必定成功，调用方必须检查 `cleanup.status`。

清理失败时，新配置已生效，界面同步保存状态、清除过期测试结果，并显示失败原因和再次保存的操作提示。再次保存沿用串行队列，重新清理所有相关标签页；已清理的候选允许重复处理，已观察到的目标和下载任务保留。不自动重试，也不以回滚配置掩盖部分完成。配置读取失败仍禁止覆盖，草稿测试不受保存结果契约影响。

新增可选字段仅由同一扩展版本的前后台消费，不提供旧前后台混用适配，不迁移或清空已有工具及识别配置。更换扩展产物后刷新设置页面；旧产物不支持新选项，不应读取含新行为的配置来冒充等价回退。Native 检查点及二进制帧格式未改变。

## 设置界面

`SettingsView.vue` 统一提供常规、识别规则、URL 提取、外部工具和输出模板的导航。删除原 `ConfigurationPanels.vue` 的第二套页签布局，各功能面板仍拥有自己的草稿与保存操作。`KeepAlive` 按分类独立缓存，切换分类不保存或丢弃草稿；网页工作区不挂载特权配置面板。

桌面使用左侧导航、右侧内容；窄窗口使用可横向滚动的顶部导航。沿用流萤绿色和现有色彩变量。Grid 标题行按内容高度排列，下方内容区承接最小高度的余量，避免不同分类把标题撑高；稳定滚动条槽避免页面长短变化引起横向位移。
