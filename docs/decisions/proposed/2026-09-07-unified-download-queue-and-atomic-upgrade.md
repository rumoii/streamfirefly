# Decision: 统一下载计划、任务队列与成套升级

Status: proposed

源码已实现并完成本地验证；尚未发布成套安装包，也未完成目标机器验收，因此保持 proposed。本记录取代早期协议和 HLS 决策中的新旧 Host 混用、协议 v2 兼容及 HLS v1 回退约定；多输出、密钥隐私和检查点语义不变。

## Problem

快速、详细和批量下载曾使用不同 HLS 执行路径，可靠性随入口变化；每个任务直接启动工作线程缺少全局名额限制。界面快照和事件并发更新，以及超时后的重复提交，会造成任务状态回退或重复创建。

## Proposal

- 保留原生侧栏、网页内 Shadow DOM 工作区、Vue/Pinia 与 Rust 单进程结构。仅在资源上下文、下载计划、任务状态、队列和执行引擎的实际职责边界拆分模块。
- `download-plan.ts` 统一生成 HLS 计划：点播 v2、直播 v3；默认最高画质、默认音轨、全片、不带字幕。详细入口继续支持选择。移除 HLS v1 远端 FFmpeg 执行；DASH 完整清单下载不受此变更影响。
- 扩展和 Host 成套升级；`host.info` 声明协议 v3，以及切片引擎、任务队列和请求去重能力。能力不匹配时禁用提交并提示成套更新；传输信封版本保持 1，不随功能重构改号。
- Host 独占任务与队列状态，最多同时运行 2 个任务。待执行任务不占工作线程，暂停或取消直接移出队列；恢复和重试进队尾。单任务内部连接数仍是 1–16，默认 6，与全局任务数不同。直播必须显式启动，满额拒绝，不排队等待录制。
- `task.create` 必须带 `requestId`，同一标识返回已有任务；`task.find` 用于查询不确定的提交结果。断连或超时不等于取消，客户端不得换新标识盲目重发。
- 批量确认冻结来源与候选快照；逐项准备、提交和反馈。直播、DASH 以及无法自动处理的密钥或加密情况转为单独处理；停止提交只影响尚未提交项，Host 已接受的任务不由弹窗生命周期控制。
- 来源响应带本地请求序号；旧响应不得覆盖新上下文。任务快照刷新合并为一个在途请求，期间收到事件时保留事件并重新同步；断连保留最后可见任务，重连失败不得永久缓存。
- 任务文件版本保持 1。未知版本或损坏格式拒绝写入；写入先落临时文件再原子替换。创建任务持久化失败不返回已接受，也不进入队列。Cookie、Authorization 和手动密钥不落盘。

## Alternatives considered

- 按入口保留多套 HLS 引擎：功能表面相同却具有不同的暂停、检查点和恢复语义，测试成本过高。
- 为旧扩展和旧 Host 增加兼容层：当前选择为成套交付，不再承担混合版本运行义务。
- 在 UI 中排队执行下载：关闭界面或切换来源会影响已接受任务，不符合 Native Host 所有权。
- 重写为独立服务或插件：不能解决当前状态归属问题，增加不必要的部署和接口复杂度。

## Risks

- 扩展与 Host 必须同时更新，旧任务无法依靠 HLS v1 引擎恢复。保留旧文件，重新解析创建新任务。
- 关闭浏览器或终止 Native Host 不等于仅关闭界面；点播恢复仍依赖有效检查点和重新授权，直播重启后不自动继续采集。
- 模块拆分减少职责混杂，但 Native 模块仍共享进程内 Store；这不是独立服务边界，也不是完整解耦证明。
- DASH 工作台、页面录制、外部集成、多语言、多平台及完整 1.0 发布验收不在本次交付范围内。

## Verification

- 单元层：统一计划、视频/音轨加密校验、请求去重补查、来源响应顺序、任务快照与事件竞态、批量停止和失败反馈。
- 本地 Native 集成层：HTTP、HLS 点播/直播、AES-128、暂停/停止、重启恢复；两任务上限、FIFO、恢复进队尾、排队取消、持久化失败、未知存储版本和旧 HLS 拒绝回退。
- 浏览器层：Chrome/Edge 独立配置验证真实扩展；独立 Playwright 界面夹具验证批量、时长、焦点和断连保留，Native API 为模拟。Firefox 本机缺少可执行文件，真实运行仍待验证。
- 交付层：构建与清单检查不替代 x64/ARM64 成套安装、升级、回滚及真实网站验收；本记录不据此标记 implemented。

## Rollback

停止任务和助手后，备份任务文件、检查点和已下载文件；扩展与 Host 同时回滚到同一已验证版本。旧 Host 不保证读取新运行阶段的数据，必要时恢复升级前备份，并另存升级后的副本，不直接覆盖唯一副本。回滚不自动清理任何任务目录或媒体文件。
