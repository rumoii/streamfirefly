# 决策：提取来源与工具配置单一权威

状态：proposed。源码实现及本地开发验证完成，正式验收统一安排。

## 约束

识别规则判断是否收集，提取规则生成候选，工具适配执行交接；不能让 URL 替换继承原请求凭据，或让新增提取行为暗中触发现有自动发送。

## 选择

- 提取配置独立于分类配置，输出进入资源收集层做排除、去重和来源记录，不覆盖原资源、不递归、不自动请求或发送。
- Cookie、Authorization 等请求上下文属于实际目标请求，不能从原始地址复制到新地址。只有目标网络观察才能补充目标元数据。
- 保存配置先持久化，再经标签页队列清理未观察到的派生候选；不触碰已创建任务。配置写入失败拒绝保存；写入成功后通过 `cleanup.status` 区分清理完成和失败，失败同时返回原因与实际生效配置，不能报告保存与清理均已成功。再次保存可重试清理，不自动重试或跨存储回滚。
- N_m3u8DL-RE 结构化表单与高级参数互斥，转换后删除旧表示。参数生成、预览与执行共用路径，不增加双写和兼容开关；Native 继续只负责程序校验与启动。
- 设置外壳只管理导航和缓存，各面板独立管理保存；缓存键是分类身份，标题行高度独立于页面内容长度。

未选择通用条件树、任意脚本、统一外部任务管理器或旧实现适配层；当前需求不需要这些复杂度。

## 验证与回退

实现边界和证据见 [开发说明](../../development/tools-and-extraction.md)。测试验证草稿无副作用、凭据隔离、禁止自动发送、候选清理及分类缓存；不代表真实外部下载完成。

前后台作为同一扩展产物更新。旧产物不能解释新工具选项和提取行为，不承诺带新配置回退的语义等价；不自动删除、覆盖或迁移用户配置，Native 数据格式不变。
