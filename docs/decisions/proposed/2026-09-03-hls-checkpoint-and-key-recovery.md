# Decision: HLS 切片检查点与密钥恢复

Status: proposed

本记录中的 HLS v1 回退与旧 Host 混用约定已由 `2026-09-07-unified-download-queue-and-atomic-upgrade.md` 取代。当前点播统一使用 v2 计划，直播显式使用 v3；检查点、密钥与敏感信息边界继续有效。

## Problem

由 FFmpeg 直接读取远端 HLS 清单时，流萤无法稳定展示切片级进度，也无法独立控制并发、重试和进程重启恢复。登录资源和 AES-128 密钥又包含不能持久化的敏感信息，因此检查点不能简单保存完整请求上下文。

## Proposal

- `hlsPlan.version = 2` 由扩展在 Native Host 同时声明 `hls-selection-v1`、`task-output-group-v1` 和 `hls-segment-engine-v1` 时发送；旧 Host 或缺少能力时继续使用 `hlsPlan.version = 1` 的 FFmpeg 网络读取路径。
- Native Host 是 HLS 下载状态的权威。每个任务在本地任务目录保存版本化 `checkpoint.json`，记录派生清单、轨道、Map、切片状态、字节数和重试数，不记录 Cookie、Authorization 或手动密钥。
- 点播切片使用 1–16 路并发，默认 6 路。HTTP 408、429、5xx 和明确的传输错误最多重试三次，默认按 1、2、4 秒退避；数字形式 `Retry-After` 最多等待 30 秒。401 和 403 不重试，任务转为等待来源页面重新授权。
- 检查点最多每累计 16 个结果或每秒写入一次，失败、暂停、取消和下载结束前强制刷新。任务界面进度以更短间隔汇总，避免每个切片都重写任务文件。
- Host 在响应首次 `host.info` 或 `task.list` 后只触发一次自动恢复。公开资源从检查点继续；需要登录态的任务等待用户从原候选资源补充新请求头；使用手动密钥的任务要求重新输入。扩展以稳定 `candidateId` 查找来源上下文。
- 标准 AES-128 支持清单密钥以及 Hex、Base64、密钥 URL和可选 IV。并发开始前先解密并校验第一个选定媒体切片；加密 `EXT-X-MAP` 必须具有显式 IV。SAMPLE-AES、DRM、直播和 LL-HLS 不在本阶段范围内。
- 主视频合并成功而部分字幕生成失败时，任务保持 `partial`，保留检查点供重试，不能把主视频误标为失败或重新下载已完成切片。
- HLS 凭据隔离覆盖扩展清单解析和 Native 下载：仅向原候选 URL 的同源地址发送 Cookie、Authorization；同源按协议、主机和有效端口判断。跨源清单、切片、初始化片段、音轨、字幕及密钥仍可请求，但不携带原来源凭据，扩展使用 `credentials: "omit"`；401、403 不触发跨源凭据重发。下载保留原有 Referer、Origin 上下文，预览继续使用严格模式。
- 直播接受“停止并保存”后不再派发新切片、重试失败请求或进入下一轮清单刷新，已开始的作业按现有超时结束。所有 worker 退出后，只合并本地已完成且初始化片段完整的内容，在途请求失败不覆盖保存操作；暂停或中断后的停止直接进入本地保存。原来源候选丢失、凭据过期或密钥缺失均不阻止保存；没有完整媒体时明确失败，字幕不完整时保持 `partial`。检查点读写或最终合并、发布失败仍报错，不裁剪或覆盖原恢复检查点。

## Alternatives considered

- 继续完全依赖 FFmpeg 读取远端清单：实现简单，但无法满足切片级状态、受控重试和可靠检查点恢复。
- 将 Cookie、Authorization 和密钥写入检查点：可实现无交互恢复，但扩大本地敏感信息暴露面，不符合本地任务记录的隐私边界。
- Host 启动后立即向 stdout 推送恢复事件：恢复更早，但可能在浏览器首个请求响应前产生无关联事件，破坏简单客户端的请求顺序假设。
- 每个切片完成都同步写检查点和任务文件：最直接，但大清单会产生不可接受的全量 JSON 写放大。

## Risks

- Host 被强制结束时，距离上次检查点写入不足一秒或 16 个结果的少量已完成切片可能重新下载，但不会覆盖最终输出或丢失已持久化进度。
- 登录页面导航、候选资源被移除或授权策略改变后，扩展可能无法取得新的请求头，此时任务继续保持中断，不得使用旧凭据猜测恢复。
- FFmpeg 合并仍可能因媒体编码、时间戳或容器不兼容失败；切片保留用于重试，不能将切片下载成功等同于最终媒体可播放。

## Verification

- 单元层：HLS 版本、BYTERANGE、Map、媒体序列、AES-128、密钥输入、IV、10,000 切片元数据、检查点版本和旧任务读取。
- Native 集成层：本地 HTTP 夹具覆盖普通 HLS、AES-128、错误密钥首片拦截、500 重试、403 重新授权、暂停继续、检查点删除和 Host 终止后恢复。
- 凭据与停止保存：覆盖扩展清单和 Native 请求的同源登录、跨源公开资源及重定向隔离、跨源 403 不重发凭据，以及过期凭据仍在内存、暂停、凭据或密钥缺失后的本地保存。以请求返回屏障覆盖在途切片 403/404/500、成功请求后的队列停止、两处清单刷新、首片密钥验证和检查点写入失败；输出需通过解码与轨道、时长检查。界面覆盖来源候选丢失后仍可停止、恢复下载仍需有效来源。
- 浏览器层：使用专用测试配置验证加密面板、手动密钥校验、任务切片指标和恢复入口；浏览器验证不证明第三方登录站点授权长期稳定。
- 交付层：x64 与 ARM64 内测包分别验证 PE 架构、Host capability、FFmpeg、清单、校验和及来源信息。

## Rollback

- 回滚扩展时，旧版本忽略新增任务字段；顶层任务和输出字段仍保持存储版本 1。
- 回滚 Host 时，新扩展根据 capability 不发送 v2 计划，继续使用 v1 路径。旧 Host 不读取任务目录中的 v2 检查点；卸载或删除任务时可清理对应目录。
- 一旦 v2 任务只剩检查点而运行时清单已经丢失，旧 Host 不能继续该任务；用户必须重新发起下载。回滚不会删除已完成的主视频或字幕文件。
