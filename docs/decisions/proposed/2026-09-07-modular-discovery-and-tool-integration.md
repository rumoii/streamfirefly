# Decision: 模块化发现与外部工具集成

Status: proposed

源码方案已按用户确认实施；发布验收仍待完成，因此该记录保留 proposed，不表示完整 1.0 已通过验收。

## Problem

后台脚本共享全局作用域，Native Host 通过根模块聚合依赖，前端总 Store 同时拥有不同业务状态。新增规则、模板、外部工具和捕捉会扩大隐式依赖。

## Proposal

- 保持模块化单体。扩展采用显式模块与依赖注入，构建为各浏览器的后台入口；资源、配置、预览、工作区和助手连接分别拥有状态。
- 规则与模板是可独立测试的纯业务模块。外部交接、深度搜索和捕捉使用各自的状态与生命周期，不混入内置下载状态机。
- Native Host 入口只装配；协议、输入校验、任务状态、持久化、调度和执行器通过明确引用协作，移除根作用域通配导入。
- 不保留旧实现兼容分支；成套升级扩展与助手。不自动重置、覆盖或迁移不支持的用户数据。
- 页面来源是不可信输入，不能选择程序、目标服务、保存路径或读取凭据；执行必须由用户授权的扩展上下文触发。

## Risks

- 重构必须保留现有 HTTP/HLS、队列和恢复行为，不能只证明新模块单测成功。
- 外部调用超时不能证明未执行，不自动重发未知结果。
- 捕捉需要有界内存、认证传输、持久确认与异常收尾，未验证前不得宣称可用。

## Verification

基线为 05583f3：29 项前端测试、扩展逻辑与打包契约测试、33 项 Rust 测试。后续证据须区分源码、模拟接口、真实助手、浏览器和实机包。

实施模块、状态机、资源上限和本地证据见 `docs/development/modular-discovery.md`。本次不承诺启动前缓存回溯、DRM、DASH 完整轨道选择或 Firefox/ARM64 实机验收；这些不通过兼容分支或静默降级伪装为已支持。

## Rollback

源码与构建产物成套恢复；测试只使用临时状态目录。用户已有任务、检查点和下载文件不参与测试或自动清理。
