# Decision: DASH 选轨计划与进程内恢复

Status: proposed

源码实现与本地开发验证不等于发布或统一验收。

## Problem

动态 MPD 可能仅存在于页面内存；直接向 FFmpeg 传递完整清单不能保证用户选择的轨道，也不能复用分片进度和取消边界。DASH 与 HLS 的寻址和恢复语义不同，不应复制一套队列或强套 HLS 检查点。

## Proposal

- 页面探针保留完整 MPD 文本及来源；UI 使用独立 DASH 解析器生成显式选轨计划，Host 再次校验。采用独立许可的 `mpd-parser`，独立实现。
- 计划只覆盖静态、单 Period、非加密点播。每种媒体至多一条轨道，Host 只下载计划中分片，FFmpeg 只读取本地文件合并。删除旧完整 MPD 执行分支，不增加兼容适配或静默兜底。
- HLS/DASH 共用字节范围与传输原语，保留各自解析器、执行编排和恢复规则；普通 HTTP 与已有任务调度职责不变。
- DASH 计划仅在内存中，同进程暂停/重试复用完整分片，重启后明确要求重新解析。不自动持久化临时地址和凭据，不把已完成分片标为可重启续传。
- 扩展与 Host 成套更新，以 `dash-selection-v1` 判断能力；公共协议主版本和任务存储版本不变。

该选择替代 [统一下载队列决策](2026-09-07-unified-download-queue-and-atomic-upgrade.md) 中保留 DASH 完整清单执行的边界；其 HLS、队列和原子升级规则不变。

## Alternatives considered

完整 MPD 交给 FFmpeg 无法兑现精确选轨；把 DASH 塞入 HLS 计划会混淆协议语义；通用分片框架和重启检查点超过当前业务范围，因此只抽取已有重复的传输能力。

## Risks

同进程下载可解释、可取消且模块边界清楚，但没有 DASH 重启恢复。时间轴间断、SIDX、多 Period、直播和 DRM 明确拒绝。MP4/MKV 仍受 FFmpeg 编码封装能力约束，失败不能降级为整清单下载。

## Verification

能力矩阵、限额、调用关系、命令与未验收项由 [开发说明](../../development/dash-vod.md) 维护。单元、localhost 真实下载和专用浏览器证据不代表安装态、ARM64、真实站点或长时间验收。

## Rollback

更新前结束活动任务并备份任务历史、工作目录及输出文件，扩展与 Host 同步替换。新 Host 重启后保留 DASH 历史但禁止无计划恢复。回退需先保留新数据，再成套恢复旧产物与升级前备份；不让旧 Host 自动执行新 DASH 未完成记录，不承诺旧产物理解新标识或恢复要求。
