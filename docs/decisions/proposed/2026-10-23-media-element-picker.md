# Decision: 页面媒体拾取

Status: proposed

## Problem

资源列表只能自动置顶「当前视频」：持续播放 1.5 秒、大半在可视区内的那个 `<video>`。页面上有多个视频、要的视频没在播放，或者要的是一张图片时，用户没法自己指定。同一视频的判断也只靠封面或时长：HLS 主清单和各分辨率子清单之间没有关联，多数子清单不会跟当前视频一起置顶。

## Proposal

- 资源工具栏增加「拾取」按钮，交互仿照浏览器的元素检查。点击后页面的每个 frame 进入拾取态：鼠标所在的 video、audio、img 显示品牌绿填充和标签（标签名、分辨率、时长）；点中媒体即完成拾取，Esc 或面板上的取消按钮退出。
  - 命中检测用 `elementsFromPoint` 查看整个元素栈，并深入 open shadow root，所以播放器控制层盖在视频上面也能选中。栈里没有媒体元素时，再按视频的矩形范围兜底，处理设了 `pointer-events: none` 的视频。
  - 拾取态下页面收不到按下和点击事件，不会暂停视频，也不会跟随链接。流萤面板宿主上的事件照常放行。
  - 这些捕获监听在内容脚本于 `document_start` 加载时就注册在 window 上，排在所有页面脚本之前；不在拾取时什么也不做。所以页面自己的捕获监听抢不到事件，也没法用 `stopImmediatePropagation` 拦住拾取。
  - 只处理 `isTrusted` 的事件。页面脚本合成的点击和 Esc 原样交还给页面，既不能替用户完成拾取，也不能取消拾取；合成的鼠标移动也不会移动高亮框。
  - 识别流萤面板时，比对的是工作区脚本记在扩展隔离环境全局变量 `__streamFireflyWorkspaceHost` 上的宿主元素本身，不比对 id。页面仿造同 id 的元素不会被当成面板。
  - 页面上的 Esc 只在拾取态下拦截。悬浮面板的「不拦截页面 Esc」约定照旧。
  - 高亮层放在独立的 closed Shadow DOM 宿主里，不接收鼠标事件，层级低于流萤面板。准星光标靠页面级的一条样式规则实现，拾取结束后连同宿主一起移除。
- 拾取期间，悬浮窗口让位给原位置上的一行提示条「正在拾取 · 取消 (Esc)」，拾取结束后恢复原来的窗口形态。侧栏只切换按钮状态。
- 消息协议：
  - `media.pick.start`、`media.pick.cancel`、`media.pick.clear` 按 `ui.resource-state.patch` 的方式解析标签页：网页内面板用发送者来源，侧栏用活动标签。`start` 和 `clear` 要求 `sourceContextId` 与当前一致；嗅探暂停时 `start` 返回 `sniffing_inactive`。
  - background 每个标签页只保留一个 `pickId`，用 `tabs.sendMessage` 向所有 frame 广播 `media.pick.control { active, pickId }`。
  - 内容脚本用 `media.pick.result { pickId, pick }` 上报点中的元素，用 `media.pick.cancel { pickId }` 上报 Esc。`pickId` 不匹配的结果和取消都会被拒绝。
  - 内容脚本在准备期间（`probe.install` 还没返回）收到开始拾取的通知，会先记下 `pickId`，准备好后再启动。准备失败、嗅探停用或收到停止通知时，丢弃这条记录。
  - 收到结果、取消、再次开始、嗅探暂停或停用（比如「打开时嗅探」模式下切走标签页）、页面导航（地址除 hash 外发生变化，包括同文档导航）或关闭面板时，background 都会结束会话并广播 `active: false`。内容脚本在嗅探停用时也会自行停止拾取。
  - background 不记得任何会话时（例如 Service Worker 重启后），收到的取消或结果仍会广播 `active: false`，以清理残留在各 frame 里的拾取器。会话存在但 `pickId` 对不上的旧结果不广播，免得停掉当前会话。
- 拾取内容 `{ kind, urls, poster, duration, width, height }` 经 background 校验后存为 `state.pick`：
  - `urls` 只保留 http(s) 和 blob 地址，最多 32 个，每个不超过 4096 字符；`poster` 只接受 http(s)。
  - `state.pick` 和 `focus` 一样只放在内存里，不写进 session 存储，刷新或导航后清空。只改 hash 不算导航，这和资源列表的既有行为一致。
  - UI 上下文新增 `pick` 和 `picking` 两个字段。
- `urls` 依次收集：元素当前地址、`src`、子 `<source>`，图片再加上 `srcset` 和外层 `<picture>` 的各个尺寸。
  - 拾取到的图片由 background 以 `userPicked: true` 加入列表，不受「识别图片」开关影响，用户自定义的排除规则照常生效。写入前会核对拾取时的 `sourceContextId`，结果返回途中页面跳转了就丢弃。
  - 未拾取的图片仍按开关过滤，规则保存后的重新评估也保留拾取到的图片。
- HLS 主清单与子清单的关联：
  - 页面探针上报清单成员时，给子清单和音频、字幕等 rendition 清单附上 `parentUrl`。值取主清单上报时使用的地址：GET 请求是请求地址，内存清单是其来源地址（可能是 blob）。分片、密钥和初始化片段不附带。
  - 子清单按清单结构识别：`#EXT-X-STREAM-INF` 的下一行、`#EXT-X-MEDIA` 和 `#EXT-X-I-FRAME-STREAM-INF` 的 `URI`，不要求 `.m3u8` 后缀，并以 HLS 类型上报，不再误标成分片。
  - background 把 `parentUrl` 规范化后并入候选的 `parents` 字段（取并集，最多保留 8 个），不保存 `parentUrl` 本身。
  - `parents` 和 `userPicked` 只由 background 生成：`media.add` 会剔除页面传来的这两个字段，合并时 `parents` 只从已存的数组和校验过的 `parentUrl` 重建。UI 读到非数组的 `parents` 时按空处理。
  - 带 `#EXT-X-ENDLIST` 的媒体清单，按 EXTINF 累加出 `duration` 一起上报，MSE 的 blob 视频由此能按时长匹配到子清单。
- 列表匹配：
  - 拾取组先按拾取的所有地址匹配。只有视频再走现有的封面、时长同视频判断；音频和图片只按地址和清单关系匹配。
  - 匹配结果再按 `parents` 做闭包，补上主清单、子清单和同一主清单下的兄弟清单；主清单本身不在列表里时，共享同一父地址的子清单也能互相带出。「当前视频」组复用同一套匹配，所以也带上各个分辨率。
- 排序：拾取组在任何排序方式下都排最前，组内不按「当前视频」重排，照旧把 blob 放在最后。「当前视频」组只在「嗅探顺序」下排第二。同一资源同时属于两组时只显示一次，归在拾取组。
- 配色：拾取组用品牌绿，行底色加深，标签为「已拾取」。「当前视频」标签改为中性灰。拾取加入的图片另有一个「拾取加入」标签。
- 列表顶部的状态条显示拾取对象和相关资源数量，提供「重新拾取」和 ×。没有匹配到资源时提示播放一会儿再拾取，或改用缓存捕捉；匹配到的资源都被筛选隐藏时提供「清除筛选」。

## Alternatives considered

- 拾取结果直接替换「当前视频」焦点：实现最少，但新开始播放的视频会顶掉用户的选择，不采用。
- 用覆盖整个视口的透明层接收点击：拦截更简单，但顶层 frame 的覆盖层会挡住 iframe 自己的拾取，不采用。
- 在 UI 里拉取并解析每个主清单来建立父子关系：需要额外请求，还要重复处理请求头和鉴权；探针本来就会读到清单正文，所以直接在探针里记录。

## Risks

- 拾取期间会吞掉页面上的点击，跨域 iframe 里的点击由该 frame 自己处理，体验和顶层页面一致。
- 页面级的光标样式规则可能被页面中更高优先级的 `!important` 规则覆盖。
- closed shadow root 里的播放器元素无法命中，这时只能靠视频矩形兜底。
- `parents` 是写进 session 存储的新候选字段；旧状态缺这个字段时按空处理。
- 拾取开始后才出现的 iframe 不会进入拾取态。
- 音频不做同内容副本匹配：时长相同的另一个音频不会一起置顶。
- 页面仍然可以经由探针通道上报 `parentUrl`，让它自己的资源进入拾取组的清单关系；影响限于当前页面列表的分组。
- 只关侧栏不会取消拾取：「打开时嗅探」模式下拾取会随嗅探停用一起结束，「始终嗅探」模式下需要在页面上按 Esc。
- 面板宿主按引用识别依赖工作区脚本和内容脚本共享同一个扩展隔离环境；Firefox 上这一点还没有在真实浏览器里验证。
- 工作区脚本仍按 id `streamfirefly-workspace-host` 判断是否已经挂载。页面先放一个同 id 的元素，工作区就不会挂载，5 秒后报 `workspace_ready_timeout`。这是拾取器之前就有的行为，暂不修复；要修时改为按 `__streamFireflyWorkspaceHost` 引用判断。
- 完整扩展构建原子更新，不支持新旧脚本混装。

## Verification

单元测试覆盖：
- 拾取器：穿透控制层、放行面板宿主、点击被吞、Esc 取消、嗅探停用时停止，以及 srcset 和 `<picture>` 的解析。
- background：`pickId` 校验、结果字段的清理、其他 frame 收到停止通知、图片绕过「识别图片」开关、侧栏取消、暂停与同文档导航结束拾取，以及 `parents` 的合并和校验。
- 页面探针：GET 主清单与内存主清单的成员 `parentUrl`、点播媒体清单的时长。
- UI：主清单、子清单和兄弟清单的闭包，拾取组和播放组在三种排序下的顺序及合并。

Codex CLI 0.162.0（gpt-6.1-sol）只读审查发现 10 个 P2 问题，均已修复并各配回归测试：页面伪造 `parents` 和 `userPicked`、结果途中导航、嗅探停用后会话残留、Service Worker 重启后的残留拾取器、音频误配视频、紧凑 srcset、无扩展名子清单、主清单缺席时的兄弟清单，以及拾取组内的 blob 顺序。逐个回退生产代码修复后，对应的回归测试都会失败。

随后由 pi（mimo-v2.6-pro）接手只读复审，确认这 10 项都已修好，并新发现 4 个问题：合成事件能伪造拾取；准备期间收到的拾取会丢失；页面更早注册的捕获监听会先拿到事件；页面能仿造面板宿主。这几项都已修复，各配回归测试，单独回退后测试都会失败。另有一处 ADR 表述与实现不一致（只改 hash 的跳转是否算导航），已修正。

Chrome 155 通过 web-ext 加载扩展，在本地测试页上真实点击，验证了以下行为：
- 拾取视频后，HLS 主清单和各子清单置顶；
- 「识别图片」关闭时，拾取的图片和 srcset 各尺寸加入并置顶；
- 拾取态下点击不会跟随链接；
- Esc 和 × 都能生效；
- 拾取期间面板收成提示条。

Firefox 只跑了现有的浏览器回归测试，拾取交互本身还没有在 Firefox 真机上验证。本记录尚不标记为已发布实现。
