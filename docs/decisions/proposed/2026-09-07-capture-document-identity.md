# 决策：捕捉来源按框架和文档实例隔离

状态：proposed。源码实现与本地分层验证已完成，安装态及两小时验收尚未执行。

状态依据截至 2026-09-07；历史源码基线与证据位置见 [Beta 2 开发交接](../../archive/development/capture-beta2.md)。本决策记录身份隔离的约束和取舍，当前发布验收见[正式发布流程](../../development/release.md)。

## 问题

顶层页面限定使 iframe 播放器不可选；仅使用标签页和媒体编号不能拒绝框架导航后的迟到消息。深搜开关也不能代表所有框架已成功注入。

## 方案

- 捕捉来源由标签页、框架、文档令牌和媒体源编号标识。浏览器提供 documentId 时同时校验，并对探针注入指定该文档；否则使用隔离内容脚本生成的文档令牌拒绝旧控制和数据。
- 探针在文档内记录 `URL.createObjectURL(MediaSource)` 产生的 Blob URL，并在撤销 URL 或文档销毁时失效。资源列表发起的 Blob 捕捉必须精确命中同一来源的 Blob URL，不按 MIME、发现顺序或时间做推测，也不自动切换其他媒体源。
- 来源扫描通过实际内容脚本身份与 MAIN 媒体源共同确认。开始前和开始过程中重新检查页面上下文，导航取消尚未完成的启动。
- 一个标签页最多一个活动来源。无关框架导航不终止当前捕捉；选中框架消失、导航或传输失败时终止当前会话，不自动切换来源。
- 停止先排空并取得落盘 ACK，再请求合并；UI 中“停止请求已处理”不等于“文件已保存”。Native 快照继续拥有最终状态。
- 深搜按框架记录注入结果；文档身份和启用状态同时满足才接收密钥。切换操作串行处理，站点记忆写入串行化，密钥不持久化。

## 职责与替代方案

维持模块化单体：共享类型定义浏览器消息，协调器拥有来源和生命周期，传输层拥有连接和 ACK，Native 保持落盘与合并职责，前端状态独立于通用配置。未采用统一巨型会话管理器或扩大 Native 协议来承载浏览器框架状态。

## 风险与验证

本地测试覆盖主页面、同源及跨源 iframe、来源隔离、旧文档拒绝、重复停止、启动取消、来源变化及深搜状态。真实 Chrome/Edge 测试接收端仍为 WebSocket 夹具。

安装态测试必须在隔离 CI 中使用包内扩展、Native Host 与 FFmpeg；按实际扩展 ID 注册后走真实 Native Messaging，FFprobe 校验输出时长和轨道。两小时测试连续追加不同时间戳的媒体片段，采样自有浏览器与助手进程树内存，检查停止输出。本地存在用户助手注册，不自动覆盖；这两项未执行前不得标记本决策 implemented。

## 回滚

未改变 Native 检查点和二进制帧格式，不做数据迁移或清理。回滚扩展构建产物，保留已有捕捉文件；新版前后台必须作为同一扩展产物更新，旧浏览器页面需刷新。
